# M8b: Реальный клиент через тестовый аккаунт (ADR-006)

**Статус:** M8b-1 сделан. M8b-2 и M8b-3 впереди.
**Зачем:** Bot API не может вести диалог с ask-toby (блокер real-режима, см. `deferred-work.md`). Владелец выбрал вариант A: отдельный тестовый аккаунт Telegram входит по MTProto и пишет боту как пользователь.

## Решения

1. **Вариант A** (ADR-006). Клиент Telethon `>=1.45,<2`. Mock-режим не меняется.
2. **Настройки через переменные окружения:** `TESTFORGE_TG_API_ID`, `TESTFORGE_TG_API_HASH`, `TESTFORGE_TG_SESSION`, `TESTFORGE_TG_BOT`. Секреты лежат в GitHub Secrets и в `.env`, не в YAML.
3. **Сессия создаётся один раз** скриптом `scripts/telegram_login.py`. Строка сессии даёт полный доступ к аккаунту, в репозиторий её не коммитим.
4. **`RealTelegramBot` для диалогов не используется.** Удалить его или оставить для проверки `getMe` решим в M8b-2, когда фабрика будет выбирать клиента.
5. **В M8b-1 не делаем:** редактирование сообщений бота, повторы при FloodWait, обновление сессии, ожидание нескольких ответов. Что из этого понадобится, покажет первый реальный прогон.

## Шаги

### M8b-1: клиент, скрипт входа, тесты — сделано
- `src/testforge/telegram/user_bot.py`: `TelegramUserBot` с тем же интерфейсом, что у `MockTelegramBot` (протокол `TelegramBot`).
- `scripts/telegram_login.py`: разовый вход, печатает строку сессии.
- `tests/unit/test_user_bot.py`: 16 тестов на подменном клиенте Telethon, без сети.
- Проверка: две поломки клиента (документ уходит без `force_document`, слушатель без фильтра по боту). Каждая валит свой тест.

**Приёмка:** тесты проходят, поломки ловятся, ADR-006 принят.

### M8b-2: исполнитель и настройки — следующий шаг
- Исполнитель ждёт ответы, пока ожидание не совпадёт или не истечёт `expect.timeout_sec` (отложенный пункт «опрос real-бота»).
- Фабрика `create_bot(config)` выбирает клиента по режиму.
- Проверка конфига для real-режима: вместо `TESTFORGE_BOT_TOKEN` нужны переменные `TESTFORGE_TG_*`. Примеры в `config/examples/` обновить.
- `start()` и `close()` вызывает исполнитель или CLI.
- Тесты через подменный клиент: `single_upload` проходит в real-режиме на подмене, ответы берутся с ожиданием.

**Приёмка:** `single_upload` в real-режиме на подменном клиенте получает ответы бота с ожиданием; тесты конфига проходят.

### M8b-3: первый реальный прогон — нужны данные владельца
Владелец даёт: тестовый аккаунт, `api_id` и `api_hash` с my.telegram.org, username staging-бота. Затем запускает `scripts/telegram_login.py` и кладёт четыре значения в секреты.
- Прогон `single_upload` в real-режиме. В trace есть ответы бота, раздел «Резюме» найден.
- Проверяем на живом боте: формат ответа, триггер `/analyze` (допущение M9b-5), редактирование сообщений. Результаты записываем в `deferred-work.md`.
- Перед прогоном напомнить владельцу о стоимости пайплайна бота (его просьба).

**Приёмка:** реальный прогон записан в `runs/`, в отчёте есть ответ бота.
